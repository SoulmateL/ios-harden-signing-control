# 私有仓库加密恢复设计

日期：2026-07-29

状态：等待所有者审阅

## 目标

在不使用 U 盘、自建服务器或收费服务的前提下，为新的生产 Ed25519 seed
保留可恢复副本。

真实 seed 仍只用于 GitHub Actions 中央签名，不导入团队 Mac。私有请求仓库只保存
经过成熟工具认证加密的恢复文件，解密密码只由所有者保存在 iPhone“密码”App 中。

## 已选方案

继续使用现有两个仓库：

- 公开控制仓库 `SoulmateL/ios-harden-signing-control` 保存可审查代码、公开策略和
  GitHub Actions Secret；Git 文件中不保存 seed。
- 私有请求仓库 `SoulmateL/ios-harden-signing-requests` 保存一个 `.age` 加密恢复
  文件；不保存解密密码或明文 seed。
- 所有者的 iPhone“密码”App 保存独立生成的高强度解密密码；密码不发送到聊天、
  GitHub、Issue、日志或命令参数。

私有请求仓库即使被成员克隆，也只会留下无法直接签名的密文。移除仓库成员不能删除
已经下载的密文，因此安全性依赖高强度解密密码，而不依赖 GitHub 成员撤销。

## 不采用的方案

- 明文 seed 直接提交到私有仓库：Git 历史和成员克隆会留下永久可用副本，无法撤销。
- 只保存 GitHub Actions Secret：Secret 写入后不能读回，账号或仓库迁移时无法恢复。
- 自制加密格式：容易出现缺少完整性校验、口令派生不足等问题。

## 加密方式

使用免费的 `age` 工具提供的口令加密模式。该模式使用专门的口令派生和认证加密，
能够发现密码错误或密文被修改。

安全约束：

- bootstrap 只能从交互终端读取解密密码，禁止通过命令参数、环境变量或普通文件传入；
- 解密密码必须由密码管理器随机生成，不使用姓名、生日、手机号或重复使用的密码；
- 加密文件名为
  `Recovery/skb-integrity-prod-2026-03.age`，不含明文 seed；
- 写入 GitHub 前必须现场解密密文，并与刚生成的 seed 逐字节比较；
- 验证失败、推送失败或仓库安全检查失败时，不写入生产 GitHub Secret；
- 临时明文使用权限为 `0600` 的随机临时目录，退出时清理且不进入 Git；
- 脚本、日志和最终输出只显示 Key ID、公钥和公钥指纹。

## 初始化流程

1. 验证控制仓库设置、请求仓库为私有、请求仓库 Actions 关闭，以及本地工作树状态。
2. 验证 release signer、真实 Bundle ID 和 `age` 工具。
3. 所有者先在 iPhone“密码”App 创建独立的高强度恢复密码。
4. bootstrap 在受保护的临时目录生成 32 字节随机 seed。
5. `age` 从交互终端读取密码两次，将 seed 加密为临时 `.age` 文件。
6. 立即现场解密并比较；只有完全一致才继续。
7. 将 `.age` 文件提交并推送到私有请求仓库。
8. 通过标准输入把同一 seed 写入控制仓库的
   `IOS_HARDEN_ED25519_SEED_B64` Secret。
9. 生成不含秘密的生产策略和公开收据，然后清理临时明文。
10. `PRODUCTION_READY` 继续保持为 `false`，等待 App 公钥轮换完成。

密文先安全推送、Secret 后写入。这样后半段失败时仍有可恢复密文，不会得到一个已经
写入但无法恢复的 GitHub Secret。

## 恢复流程

恢复只能由所有者在交互终端执行：

1. 从私有请求仓库取得指定 Key ID 的 `.age` 文件。
2. 所有者从 iPhone“密码”App 取出密码并在终端提示中输入。
3. 脚本解密到权限为 `0600` 的随机临时文件，验证 Base64 规范和 32 字节长度。
4. 通过标准输入重新写入控制仓库 Secret。
5. 派生并核对公钥指纹，确认仍对应
   `skb-integrity-prod-2026-03`，然后清理临时明文。

如果密码丢失或密文损坏，不尝试破解或从日志找 seed；应生成新 seed、新 Key ID、
新公钥，并再次执行 App 信任轮换。

## 与旧电脑失效的关系

这份恢复方案只解决“新 seed 如何安全备份”，不会自动删除旧 Mac 钥匙串里的副本。
要让旧电脑持有的旧 seed 失效，实际 App 验证端仍必须：

- 信任新 Key ID `skb-integrity-prod-2026-03` 和对应新公钥；
- 拒绝旧 Key ID `skb-integrity-prod-2026-01`；
- 拒绝旧 Key ID `skb-integrity-prod-2026-02`；
- 发布并验证包含新信任策略的 App 版本。

## 验证

实现必须通过以下不接触生产 seed 的检查：

- 契约测试确认 bootstrap 使用 `age` 交互口令模式，禁止参数和环境变量传密码；
- fixture 测试确认加密后可解密为原测试 seed；
- 错误密码和被修改的密文必须失败；
- 请求仓库中不得出现 fixture 明文或任何生产 seed 文件；
- bootstrap 必须在密文验证和推送成功后才调用 `gh secret set`；
- 恢复脚本必须核对派生公钥指纹，并且不回显 seed 或密码；
- 全部 Swift 测试、仓库安全契约和历史秘密扫描继续通过。

## 上线门禁

本文档和后续脚本改动不生成生产 seed。只有真实 Bundle ID 已确认、所有者已经在
iPhone“密码”App 建立独立恢复密码、所有测试通过，并由所有者在 Mac 现场单独确认
后，才可运行生产 bootstrap。

即使 bootstrap 成功，也不得自动把 `PRODUCTION_READY` 改为 `true`。旧 Key ID
撤销、App 更新、非生产演练和最终启用仍是独立步骤。
